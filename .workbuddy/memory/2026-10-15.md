## 小程序审核风险排查（只查不改）

用户问「会不会有审核风险」。查证后新增 `docs/review-checklist.md`（并挂进 docs/README.md 索引），
没有改任何代码 —— 「工具」tab 怎么处理、要不要立刻补注销，是需要产品决策的两件事。

**四条会直接驳回的**：

1. **`pages/tools`（tabBar 第 3 项）整页是 web-view** → `tools.wxml` 全文只有一个
   `<web-view src>`，src 指向 `{base}/tools?handoff=`。业务域名仅非个人主体可配，
   本项目是个人主体（`docs/tools.md` 自己写着「配不了，这一栏会打不开」）→ 真机必白屏
   → 审核判「功能不可用」。文档里是**已知取舍**，但带着提审就是必拒。
2. **没有账号注销**：后端 `auth.ts` 只有 register / login / wechat 与 me 的
   get / nickname / wechat-bind；全项目搜不到删除账号的接口，`pages/me` 只有退出登录。
3. **隐私声明缺项**：调用点只有两处 —— `utils/image.js` 的 `wx.chooseMedia`（摄像头、相册）、
   `ai-panel.js` 的 `wx.getRecorderManager`（麦克风）；还需声明图像/语音会传给第三方模型
   （硅基流动、讯飞）。代码里无 `onNeedPrivacyAuthorization`（靠平台自动弹窗可行），
   但后台指引没配时真机上这两个接口直接失败。小程序内也没有隐私政策入口
   （「关于记账」是个 showModal）。
4. **`CLOUD_ENV` 仍是空串** → transport 降级 `direct` → 体验版/审核版走 wx.request 直连
   `https://ledger-7aie87ej.sealosbja.site`，域名进不了白名单就是满屏加载失败。

**中危**：`src/moderation/` 违禁词检查尚未接入任何接口（昵称在成员间可见、反馈内容算 UGC）；
积分用途没写在界面上（实际只抵扣 AI 识别用量，本身合规）；服务类目待确认。

**做对的**：未登录也能浏览（`app.js` 有注释）、无位置/通讯录/手机号/头像昵称收集、
除 tools 外无 web-view。

## 追问：「审核时把工具里的内容清空，再审核呢」

**不行。**查证依据：

- 《运营规范》**5.19「绕开、规避或对抗平台审核监管的行为」**第一句：「小程序提交审核的
  版本应与小程序实际发布、上线运营的版本一致。」
- 官方《关于小程序恶意对抗平台规则的违规行为公告》把「**提审环节通过技术手段将违规内容
  隐藏**，使审核侧看到的内容与实际运营内容无关」列为反面案例，定性**「最恶意的失信行为」**，
  判罚封禁功能 → 下架 → 封号，并「对其**同主体或关联的开发者**后续的**代码提审、申诉
  解封、帐号注册**流程带来持续影响」。
- 检测比想象宽：线上是**持续性监管**；社区有开发者反馈「提审后一行代码没改、只更新了
  图文内容样式」照样被判「线上版本和提审版本存在较大差异」。
- 本项目的形态尤其危险：`pages/tools` 的 web-view `src` 由 `/api/v1/webview/handoff`
  交接码 + `config.getBaseUrl()` 拼出，归属由服务端 `app_configs` 下发、**改完即生效
  不发版**——「审核时关掉、过审后打开」连代码都不用动，是典型的服务端动态开关。
- 而且**就算侥幸过审也没用**：个人主体无业务域名配置入口（官方文档：仅非个人主体可配），
  上线后用户点进「工具」看到的仍是「工具页打不开」。冒封号风险换一个报错 tab。

给用户摆了三条路（① 从 tabBar 摘掉 ② 工具页改原生 ③ 换非个人主体 + 备案 + 配域名），
并建议 ① 短期解雷 + ③ 长期保架构。**用户跳过了选择，未动任何代码。**
