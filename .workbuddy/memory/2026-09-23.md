# 2026-09-23

## 小程序方案决议（重要）

- **目标**：新增原生微信小程序 `miniprogram/`，功能全量对齐 `web/`（H5）。
- **技术栈**：原生小程序（WXML/WXSS/JS，CommonJS），不用 Taro / uni-app。后端地址支持本地与线上切换。
- **架构决议**：先做全原生，**预留 web-view 接入点**（`pages/webview/`）、后续可把长尾页（统计报表/导入/预算/设置/成员）改走 web-view。
  - 原因：用户希望「改动不频繁提审」。web-view 是最省审核的手段，但有硬门槛。
  - **硬门槛（已核实官方文档）**：业务域名「仅支持非个人主体类型的小程序和小游戏账号可配置」，个人主体完全不能用 web-view；域名还需 ICP 备案 + 根目录校验文件；小程序运营规范第 8.4 条禁止以「内嵌网页」绕开平台规则，**纯 web-view 壳会被审核驳回**。
  - **当前状态**：用户现有小程序是**个人主体** → 混合方案暂不可行。用户决定**换企业/个体户主体**（新注册一个小程序，因为个人主体注册后不可变更，个人→企业即便走公证书也成本高）。
  - **待办（主体换好后）**：① 后台配业务域名；② Worker 加 `MP_verify_*.txt` 显式路由（当前 `not_found_handling = "single-page-application"` 会把校验文件请求兜底成 index.html，导致校验失败）；③ 新增「一次性 code 换 token」接口给 web-view 里的 H5 用（web-view 内拿不到 `wx.login`）；④ H5 侧支持用 code 重建会话（web-view 的 localStorage 不保证长期保留）。
- **不违规的免审红利**（个人主体也能用）：业务逻辑继续下沉 Cloudflare Worker（改完 deploy 即生效）；业务配置（分类/账户模板、表单字段、文案）由接口下发。边界：**不得下发可执行代码或违法内容**。

## 已开始的小程序骨架

- `miniprogram/utils/gbk-table.js`：GBK 双字节解码表（23940 项，73913 字节），由 `miniprogram/tools/gen-gbk-table.py` 生成。用途：微信/支付宝导出的账单 CSV 多为 GBK，而小程序运行时没有 `TextDecoder('gbk')`。索引公式 `(lead-0x81)*190 + (trail-0x40-(trail>0x7F?1:0))`，已用真实 GBK 字节验证通过。
- 注意：`ledger/package.json` 有 `"type": "module"`，所以 `miniprogram/` 下的 `.js` 用 node 直接 `require` 会被当 ESM，本地验证需复制成 `.cjs`。

## 关键后端契约（小程序要对接）

- 用户接口：`Authorization: Bearer <jwt>` + `X-Ledger-Id`；金额整数分；月份按 `Asia/Shanghai`。
- 微信登录：`POST /api/v1/auth/wechat` body `{code}`，新建账号返回 201，已存在返回 200；返回 `{token,user{has_password,wechat_bound},ledgers}`。
- 绑定已有账号：`POST /api/v1/me/wechat/bind` `{username,password}` → **必须替换本地 token**。
- 语音：`GET /api/v1/speech/status`、`POST /api/v1/speech/transcribe`（multipart 字段 `file`，mime 需 `audio/*` 或 `application/octet-stream`）。
- 收据：`POST /api/v1/transactions/:id/receipt`（mime 严格限定 `image/jpeg|png|webp`，所以上传要手工拼 multipart 显式写 Content-Type，不能用 `wx.uploadFile` 靠默认值）。
- 导入：`POST /api/v1/imports/preview`（`{kind:'text',text,filename,use_ai}`，不落库）→ `POST /api/v1/imports/commit`（`{source,filename,ai_used,rows:[{date,amount_cents,direction,note,category_id,account_id,favor_contact,favor_kind,favor_occasion}]}`）→ `GET /api/v1/imports/batches` / `POST .../:id/undo`。
- 兜底：进首页会 `POST /api/v1/recurrences/run` 补记周期记账。

## Bug：微信登录后被踢回登录页（本日第六轮）

**症状**：微信登录成功 → 进入明细页 → 又被弹回登录页。

**根因链（三环，缺一不成）**
1. `src/app.ts` 账本中间件对「已通过鉴权、但没带 `X-Ledger-Id`」返回 **401**「缺少账本」。
2. 客户端（小程序 `utils/request.js`、H5 `web/src/api.ts`）把 **401 = 登录过期**
   → `session.clear()` + `reLaunch('/pages/login/login')`。
3. 触发点：`pages/home/home.js`（和 `pages/speak/speak.js`）用 `withLedger: false` 调
   `GET /api/v1/speech/status`（它只读全局 `ai_profiles`，确实不需要账本），
   但该路径**不在** `LEDGER_OPTIONAL` 白名单里 → 401 → 刚登录的用户被踢出去。

H5 侧没暴露这个问题，是因为 `web/src/voice.ts` 调它时走了默认（带了账本头）。

**修复（两处服务端 + 一处客户端）**
- `src/app.ts`：`if (!ledgerId) throw unauthorized('缺少账本')` → **`badRequest('缺少账本')`（400）**。
  用户已通过鉴权、只是请求不合法，语义上不是「未登录」。
- `src/app.ts`：`LEDGER_OPTIONAL` 加入 `/api/v1/speech/status`。
- `miniprogram/utils/request.js`：401 分支加 **token 一致性保护** ——
  `token`（发请求时捕获）必须等于 `session.getToken()` 才清会话跳登录。
  这样登录前发出的请求、换账号后的迟到响应，都不会误伤新会话；
  而「本来就没登录」的情况（两端都空）仍会正常跳登录页。

**测试**：新增 `test/ledger-header.test.ts`（4 条：缺账本=400、未登录=401、speech/status 免账本=200、越权=403）；
`test/imports.test.ts` 里那条「未带 X-Ledger-Id 时拒绝」的断言由 401 改为 400。
`typecheck` 通过、**90 个测试全绿**。已部署：Version `9524fb56-05e6-48ae-ac50-59e445108c43`。

**教训（值得固化）**：**401 只能表示「未认证」**。凡是「已认证但请求不合法/上下文缺失」都必须用 400，
否则任何客户端都会把它当成掉登录并清会话。这类 bug 的现象是「操作到一半被弹回登录页」，
且因为它发生在登录成功之后，很容易误判成登录本身有问题。

## 【重要】体验版离不开真机调试：域名白名单 + 备案死结

用户问「为什么必须本地开真机调试，关了是不是就不能用了」。

**根因**：`project.config.json` / `project.private.config.json` 里 `urlCheck: false`
（= 开发者工具勾了「不校验合法域名」）。这个开关**只对开发者工具模拟器和真机调试通道生效**；
体验版 / 正式版正常打开走微信客户端的网络栈，会严格校验「服务器域名」白名单，
`https://ledger.hxsmj.top` 不在白名单里 → 请求全被拦（`request:fail url not in domain list`）。
真机调试本质是远程调试，代码与设置都来自本地工具，所以电脑一关就断。

**真正的死结**：微信要求 request 合法域名**必须已完成 ICP 备案**，而
`hxsmj.top` 的 NS 是 `ophelia/jakub.ns.cloudflare.com`、后端是 Cloudflare Worker ——
**没有境内接入商，这个域名根本没法备案**，所以也就加不进白名单。
⇒ 现状下体验版/正式版永远跑不起来（不是配置问题，是结构问题）。

**不靠电脑的临时办法**：手机端（开发版/体验版）右上角 `···` → 「开发调试」→
打开「不校验合法域名」，重启小程序即可，不需要电脑。但重启后可能要重新打开，
且仅开发版/体验版可用，正式版没有任何绕过手段。

**三条出路**：
1. 备案 + 境内接入：域名走境内云厂商做 ICP 备案，解析/反代回 Cloudflare Worker（备案要求
   域名解析在境内接入商，纯 Cloudflare 解析会被注销备案）。之后才能配白名单，一劳永逸。
2. 迁微信云托管：`wx.cloud.callContainer` **无需域名、无需备案、无需在 MP 后台配服务器域名**，
   走微信内网还自带 openid。代价是 Worker 要容器化（Hono 能直接跑，改动中等）。这是唯一
   「不用备案」的正路。云开发 AnyService 同理。注意云托管默认公网域名不能用于生产。
3. 只做内部测试：手机端开「开发调试」凑合。

**顺带确认**：当前所有网络请求（含收据 multipart 上传、语音）都走 `wx.request`
（`request.upload` 用 `wx.uploadFile` 但暂无调用方），所以将来只需配 **request 合法域名**
一类；若以后用 `wx.uploadFile` 或加载网络图片，再补 uploadFile / downloadFile 域名。

**状态**：仅调研 + 记录，未改代码。

## 日历「一片空白」的真正原因：漏了 wx:for-item（17:05）
