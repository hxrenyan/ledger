# 记分与通用心跳

## 1. 范围与规则

功能名「记分」，独立于账本；记分采用玩家间转分：普通成员只能从系统自动绑定的本人身份给其他玩家转分；房主默认也从本人身份转出，点「代转」按钮时才可指定任意转出方和接收方。每笔转分为正整数，来源方等额扣分、接收方加分，房间分数总和不变。历史只追加，记错通过反向转分纠正。不影响余额、收据、人情及收支统计。

每账号最多一个有效进行中房间（创建或加入均占用）；同房间重复加入直达，跨房间返回 409。通过邀请码加入时服务端按账号昵称（为空则用户名）自动创建并绑定本人玩家身份，重试加入不会重复创建；重名自动添加序号。房主创建的未认领且当前分数为 0 的玩家可删除，已有非零余额需先转平；已认领玩家不能删除。普通成员退出后清除身份绑定但保留玩家和历史；房主需结束房间。结束房间只读保留 7 天。24 小时无有效业务操作自动结束，读取、心跳、重复加入和幂等重试不续期。自动结束时刻为最后操作加 24 小时。房间最多 10 个成员和 10 个玩家；玩家满时新成员不能加入，房主需先删除未认领且分数为 0 的玩家。

每房间最多 10 个成员、10 个玩家。单次转分为 1–1000000 整数，累计绝对值最多 1000000000；允许来源方分数为负。玩家 ID 稳定；房主创建玩家和管理玩家，已认领玩家不可删除，可停用。房主可代任何玩家转分，普通成员仅能从本人身份转出。邀请为随机短码和随机分享凭证，重置同时失效。首期要求登录。

## 2. 数据与原子性

仅 `score_rooms`、`score_entries` 两表；成员和玩家状态保存在房间 JSON。`rev` 为房间版本。分数更新、历史、版本及活动时间在 db.batch 内原子执行，版本冲突整批回滚并有限重试。创建/加入语句同时检查全局有效房间唯一性，不能仅事务外检查。操作号唯一约束防重复，内容不一致返回 409。

表结构仅在 sql/schema.sql；迁移 `2026-11-04-score.sql` 用 `@schema-tables` 按表名从权威 schema 提取，不维护第二份建表语句。清理通过 db.batch 先删历史后删房间，无外键。每分钟后台兜底，接口读写也校验生命周期。

## 3. 接口

记分接口前缀 `/api/v1/score`，需用户鉴权，不依赖账本头。

- GET /rooms → `{items:[房间摘要]}`，仅本人参与且尚未清理的房间。
- POST /rooms，`{name?,players?:[名称]}` → 房间详情，201；`players` 为其他玩家，可为空。服务端按房主昵称（为空则用户名）自动绑定房主本人玩家：名单中有同名玩家则直接绑定该玩家，否则追加一位；含房主最多 10 位，超出返回 400。旧客户端照常传名单，行为兼容；短邀请码为 4 位数字，分享令牌仍为随机长令牌。
- POST /join，`{code}` 或 `{token}` → 房间详情。
- GET /rooms/:id → `{id,name,owner_id,rev,status,ended_at,players,members,invite_code,invite_token}`，分数和版本来自同一状态。
- POST /rooms/:id/players，`{name}` → 房间详情，限房主。
- DELETE /rooms/:id/players/:playerId → 房间详情，限房主，仅可删除未认领且分数为 0 的玩家；其历史快照保留。
- PATCH /rooms/:id/players/:playerId，`{name?,disabled?}` → 房间详情，限房主。
- POST /rooms/:id/players/:playerId/claim → 房间详情；供旧房间（房主未绑定身份）认领一位未认领玩家，小程序在房主「···」管理玩家里显示「设为我的身份」。
- POST /rooms/:id/entries，`{to_player_id,delta,request_id}` → `{entry,room}`；房主另传 `from_player_id` 指定来源，普通成员的来源由服务端绑定账号决定；一次写入原子更新双方分数并追加一条转分历史。幂等重复返回原 entry 和当前 room。
- GET /rooms/:id/entries，`?before=记录ID&limit=20` → `{items,next}`；倒序游标，含玩家名快照、delta、score_after、记录人和时间。
- POST /rooms/:id/leave → `{ok:true}`。
- POST /rooms/:id/end → 房间详情，限房主。
- POST /rooms/:id/invite/reset → 房间详情，限房主。

非成员 403；已结束写入 409；不存在或清理后 404。邀请加入限流。

## 4. 心跳

POST /api/v1/app/heartbeat，可匿名公共读取，有 token 时必须验证用户。请求 `{s:{ann:0,"game:123":17}}`，最多 8 个资源、最多一个 game。无变化返回 `{}`；变化仅返回 `{s:{"game:123":18}}`；不存在或无权限返回 `{x:["game:123"]}`。未知资源及非法版本返回 400。房间过期状态变化也触发版本差异。

公告通过 GET /api/v1/app/announcements 返回 `{rev,items}`；公共公告配置存 app_configs 的 `app.announcements`，后台 GET/PUT /api/v1/admin/announcements，PUT `{items:[{id,title,body}]}`，每次修改版本递增，空列表表示下架。Web 管理后台的「公告」面板可编辑并发布；客户端非打断式在原生工具页显示公告。工具页切换为 H5 时公告卡片与记分入口不显示（分享卡片仍可进入原生记分页）。可后续扩展通知处理器，不远程执行任意接口。

小程序只维护一个调度器，普通页面 10 秒，房间页面 5 秒；前台立即检查、后台停止、网络恢复立即检查；请求完成后再调度，不并发重叠。失败退避最多 60 秒。资源回调成功应用详情后才确认版本。账号/页面变更令牌丢弃旧响应；401 静默，不能由心跳反复强制跳登录。现有强制更新检查独立保留。

## 5. 界面与验证

工具原生页增加记分入口；分享路径直接进入原生记分页，不依赖工具页 H5 归属。首期记分仅原生小程序支持，工具配置为 H5 时不会显示原生记分入口，可通过分享卡片进入；未增加 H5 记分页。记分页支持创建、邀请码加入、当前和历史房间、自动身份、房主玩家管理、普通成员本人转出、房主指定双方转分、历史、退出与结束。房主创建房间时自动绑定本人身份，可选填其他待认领玩家（可留空），受邀成员加入后自动创建本人身份；转分默认从本人转出，房主开启代转后可让任意玩家转给其他玩家，普通成员只能从本人身份给别人转分。正整数转分在同一事务中等额扣减和增加。

房间页交互：顶部显示房间名、状态、玩家数与总分，右上「···」菜单收纳低频操作（房主：添加玩家、重置邀请、结束房间；成员：退出房间；均含返回房间列表）；邀请码点击即复制，旁边「邀请好友」直接分享。点任一可用玩家行即打开转分底部弹层并预选其为接收方；底部固定「转分」按钮（从本人转出）；房主另有「代转」按钮，可指定任意转出方和接收方。「转分」弹层不展示转出方（固定为本人），只选转给谁，接收方不含本人，确认按钮显示「转给 某人 分数」；「代转」弹层才展示「从谁转出 / 转给谁」两行，「代转」可选任意转出方，点到对方已选的玩家时双方互换。房主进入尚无本人身份的进行中房间（旧后端所建）时，小程序自动用邀请凭证调用一次 POST /join 补建本人身份；仍无身份时点「转分」会先弹出「你是哪位玩家」（认领未认领玩家或用昵称新增自己，经 POST /players 与 /claim），绑定后直接进入只选转给谁的弹层；「代转」不需要本人身份。候选只剩一人时自动选中。分数可输入或点快捷值 1/2/5/10/20/50/100，代转确认按钮显示「转出 → 接收 分数」，网络超时后显示「重试确认」并沿用原操作号。房主在玩家行「···」管理玩家，列表末尾「＋ 添加玩家」。历史时间当天只显示时分。

自动测试覆盖并发记分、同账号并发创建/加入、重试幂等、权限、过期/结束竞态、清理孤儿数据、心跳瘦响应和生命周期、输入草稿不被同步清空。迁移前后检查两表数量，孤儿计数应为 0；用 EXPLAIN QUERY PLAN 检查按房间历史游标及结束清理索引。
