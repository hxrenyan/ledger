### 4.3 构建并发布后端与 H5

H5 和 Web 管理后台随同一镜像发布，没有独立 H5 上线步骤。网页构建必须先完成，`public/` 不在 Git 中，不能复用不明来源的旧产物。

本次镜像采用版本标签；以下 `v1.2.0` 仅为示例，执行前替换为确定的实际发布版本，不能直接把示例当成本次版本。标签发布后不再覆盖，修复重发使用新版本号；保留历史版本以便回滚。后端版本与小程序版本不同时在第 1 节分别登记。

在仓库根执行：

```bash
RELEASE_VERSION=v1.2.0
RELEASE_IMAGE="ccr.ccs.tencentyun.com/ledger-qqhzy/ledger:${RELEASE_VERSION}"
npm run build:web
docker build --platform linux/amd64 -t "$RELEASE_IMAGE" .
```

确认已登录腾讯云镜像仓库；未登录时通过 `docker login ccr.ccs.tencentyun.com` 交互登录。随后执行：

```bash
docker push "$RELEASE_IMAGE"
LEDGER_CONTAINER=$(kubectl --context 7aie87ej@sealos -n ns-7aie87ej get statefulset ledger -o jsonpath='{.spec.template.spec.containers[0].name}')
kubectl --context 7aie87ej@sealos -n ns-7aie87ej set image statefulset/ledger "${LEDGER_CONTAINER}=${RELEASE_IMAGE}"
kubectl --context 7aie87ej@sealos -n ns-7aie87ej rollout status statefulset/ledger
kubectl --context 7aie87ej@sealos -n ns-7aie87ej logs pod/ledger-0 --tail=100
curl --fail --silent --show-error https://ledger-7aie87ej.sealosbja.site/api/health
```

记录版本标签、推送摘要和 Pod 实际镜像摘要并核对一致。通过更新镜像字段触发部署，无需另行滚动重启。健康接口应返回 `{"ok":true,"service":"ledger"}`，并检查网页、后台与 H5 日历能正常加载。单副本重启期间可能有短暂请求失败，发布后需确认恢复。

数据库启动顺序为 `ensureMigrated` 后执行记分清理，`ensureMigrated` 从权威 `sql/schema.sql` 创建新表；本次两张表应在启动时建立。增量文件 `2026-11-04-score.sql` 也支持从权威 schema 提取相同定义，但启动不会自动执行迁移文件。

本次采用启动建表路径，随后按 [记分迁移验证](../../sql/README.md#记分迁移验证) 检查两表数量、孤儿数据与查询计划。首次创建应为空，有数据时不能清空。不要为本次新增表直接盲跑全部历史迁移；生产镜像未包含 `scripts/migrate.mjs`，不能直接假设容器内可运行 `npm run db:migrate`。启动建表失败时先定位失败原因，暂停小程序发布。
