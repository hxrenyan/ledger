# 小程序发版记录

每次小程序发版单独建一篇记录，保存本次变更、兼容性评估、验证结果和实际发布时间，方便后续排查与回溯。

## 记录方式

- 复制 [TEMPLATE.md](TEMPLATE.md)，文件命名为 `YYYY-MM-DD-v版本号.md`，例如 `2026-11-04-v1.2.0.md`。
- 提审前创建记录，发布后补充审核结果、实际发布时间和上线验证结果；未发布的版本明确标注状态。
- 小程序版本号以微信公众平台上传版本为准，提交号填写实际发布代码的 Git 提交号。后端镜像使用版本标签，已发布标签不得覆盖；记录本次和回滚目标的版本标签、镜像摘要，并保留可拉取的历史镜像。
- 默认必须兼容历史小程序版本；若明确放弃兼容，记录用户确认、影响版本和处理方案。
- 将记录加入下表，按发布时间倒序排列。尚未确认的信息填「待确认」，未执行的验证填「未验证」，不要将计划写成已完成。

## 发版列表

版本号尚未确定的候选记录先使用 `YYYY-MM-DD-pending.md`，确认上传版本后再按命名规范重命名并更新链接。
