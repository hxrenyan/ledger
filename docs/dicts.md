# 字典

以后要复用的标签、选项，都放在 `dict_items`，不要为每一种配置另建一张表。

`kind` 和 `name` 都是字符串。`kind` 是用途代码，小写字母开头，只能含小写字母、数字和下划线，最长 32。`ledger_id` 为空表示公共字典，所有账本都能读到；有值则只属于该账本。同一用途下，公共项的名称不重复，每个账本自己的名称也不重复。账本里新增同名标签时，直接用已有的公共项。不使用数据库外键；业务表自己留 `*_id`，写入前由应用确认这条字典项是公共的，或属于当前账本。

目前只有一种用途：

| `kind` | 名称 | 用在哪 |
|--------|------|--------|
| `contact_date` | 1–16 字 | 联系人日子。`contacts.date_item_id` 指向这里，`0` 表示没记。规则见 [favors.md](favors.md) |

## 接口

要登录，并带当前账本。

`GET /api/v1/dicts?kind=contact_date`

返回当前账本和公共字典里未归档的项：`{ items: [{ id, kind, name, sort_order }] }`。公共项在前，然后按 `sort_order`、`id` 升序。

`POST /api/v1/dicts`

body `{ kind, name }`。写入当前账本。`shared: true` 时 `ledger_id` 为空，写成公共字典。同名已存在就直接返回那一条；之前归档过的会恢复。日子标签的名称规则与联系人日子相同。

删除某个字典项时，要先处理还指着它的业务数据，不能只删字典行。
