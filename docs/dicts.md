# 字典

以后要复用的标签、选项，都放在 `dict_items`，不要为每一种配置另建一张表。

`kind` 和 `name` 都是字符串。`kind` 是用途代码，小写字母开头，只能含小写字母、数字和下划线，最长 32。`ledger_id`、`user_id` 都为空表示公共字典；有 `ledger_id` 表示只属于该账本；有 `user_id` 表示只属于该账号。两个归属字段不能同时有值。同一用途下，各范围内的名称不重复；新增时优先复用同名公共项。`contact_date` 属于当前账本主人账号，所以同一主人跨账本共用标签。其他私有字典仍属于账本。不使用数据库外键；业务表自己留 `*_id`，写入前由应用确认范围。

旧库未显式迁移联系人归属前，`contact_date` 的查询和新增仍使用当前账本范围；服务启动不会自动切换。新库及已迁移的库使用上述账号范围，接口字段不变，见 [迁移说明](../sql/README.md#联系人归属迁移)。

目前只有一种用途：

| `kind` | 名称 | 用在哪 |
|--------|------|--------|
| `contact_date` | 1–16 字 | 联系人日子。`contact_dates.item_id` 指向这里。一个人可以有多条，规则见 [favors.md](favors.md) |

## 接口

要登录，并带当前账本。

`GET /api/v1/dicts?kind=contact_date`

`contact_date` 返回当前账本主人账号和公共字典中的未归档项；其他类型返回当前账本和公共项。结果为 `{ items: [{ id, kind, name, sort_order }] }`。公共项在前，然后按 `sort_order`、`id` 升序。

`POST /api/v1/dicts`

body `{ kind, name }`。普通私有项写入当前账本；`contact_date` 写入当前账本主人的账号。`shared: true` 时两个归属字段都为空，写成公共字典。同名已存在就直接返回那一条；之前归档过的会恢复。日子标签的名称规则与联系人日子相同。

删除某个字典项时，要先处理还指着它的业务数据，不能只删字典行。
