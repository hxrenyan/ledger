# 提审前自查

上传体验版、提交审核之前过一遍这份清单。

**审核是在真机 + 真实客户端上跑的**，不是开发者工具。工具里 `urlCheck: false` 只免开
发者工具与真机调试两条通道的校验，体验版与审核版一律走「服务器域名」白名单 ——
所以「工具里好好的」证明不了审核能用。

本项目是**个人主体**（见 [tools.md](tools.md)），业务域名、微信支付这些非个人主体
才能用的能力一律拿不到。

## 一、会直接驳回

### 1. 「工具」tab 整页是 web-view

| | |
|---|---|
| 位置 | `app.json` tabBar 第 3 项 → `pages/tools/tools` |
| 实现 | `tools.wxml` 全文只有一个 `<web-view src="{{src}}">`，src = `config.getBaseUrl() + '/tools?handoff=<code>'` |
| 网页侧 | `web/src/pages/tools/`：工具清单 + 联系人管理 |
| 问题 | web-view 只能加载**业务域名**，业务域名仅**非个人主体**可配置 |
| 后果 | 真机上这一栏必然打不开（`onWebError` 的文案自己就写着「请确认业务域名已配置」）。审核员点进去是空白页 → 判「功能不可用」驳回 |

`tools.md` 里已写明「个人主体的小程序配不了，这一栏会打不开」—— 这是**已知取舍**，
但带着它提审就是必拒，动身前必须先处理：

- **改成原生页**：工具清单与各工具做进小程序（最稳，推荐）
- **从 tabBar 摘掉**：入口收进「我的」，tabBar 回到明细 / 人情 / 我的三项
- **保留**：只在换成非个人主体 + 配好业务域名之后才可以

另外，运营规范本身也禁止「用网页承载小程序主要功能」，tabBar 主页面做成纯壳尤其明显 ——
即便换了主体也建议别这么放。

### 2. 没有账号注销入口

| | |
|---|---|
| 现状 | 有注册（`POST /api/v1/auth/register`）与微信登录，但全项目没有任何删除账号的接口 |
| 证据 | `src/routes/auth.ts` 只有 `auth/register`、`auth/login`、`auth/wechat`、`me`、`me/nickname`、`me/wechat/bind`；`pages/me` 只有「退出登录」 |
| 后果 | 「未提供账号注销功能」是常见退回理由；PIPL 也要求提供删除个人信息的途径 |

要做：后端加注销接口（逻辑删除用户 + 清理 `user_identities` / 成员关系 / 积分与签到记录，
`db.batch` 内原子执行），`me` 页加「注销账号」入口并二次确认。

### 3. 隐私声明缺项

小程序里会触发隐私校验的调用只有两处，但两处都在核心链路上：

| 位置 | 接口 | 需在指引里声明 |
|---|---|---|
| `miniprogram/utils/image.js` | `wx.chooseMedia` | 摄像头、相册 |
| `miniprogram/components/ai-panel/ai-panel.js` | `wx.getRecorderManager` | 麦克风 |

后台「设置 → 服务内容声明 → 用户隐私保护指引」必须勾选上述三项。另外还要说明
**图像与语音会上传给第三方模型服务做识别**（`src/ocr/vision.ts` 走硅基流动、
`src/speech/asr.ts` 走讯飞）—— 不声明即属违规共享用户信息。

代码侧没有 `onNeedPrivacyAuthorization` 之类的处理，这本身不算错（基础库会自动弹窗），
但后台没配指引时真机上这两个接口会**直接调用失败**，表现是拍照记账、语音记账点不动。

小程序内也没有隐私政策 / 用户协议的入口：「我的 → 关于记账」只是一个 `showModal` 弹窗，
建议补上政策链接。

### 4. 云函数开关没打开，审核版可能整个连不上

```js
// miniprogram/config.js
prod: { key: 'prod', label: '线上', api: PROD_API, transport: 'cloud' },
const CLOUD_ENV = ''   // ← 空串
```

`CLOUD_ENV` 为空时 `transport` 自动降级成 `direct`，体验版与审核版会走 `wx.request`
直连 `https://ledger-7aie87ej.sealosbja.site`。这个域名如果进不了「request 合法域名」
白名单（要求 ICP 备案），审核员一打开就是满屏加载失败 —— 比功能少更致命。

两条路选一条：确认该域名能加进白名单；或按原计划开通云开发 → 填 `CLOUD_ENV` →
上传并部署 `cloudfunctions/ledgerProxy`。

## 二、可能被追问

### 5. 内容安全还没接入

`src/moderation/` 有一套本地违禁词检查（见 [moderation.md](moderation.md)），
但**尚未接入任何接口**。可能被问到的地方：

- 昵称（`POST /api/v1/me/nickname`）—— 会在账本成员之间互相可见，属于展示给他人的 UGC
- 意见反馈内容（`POST /api/v1/feedbacks`）
- 交易备注、导入文本

接入时注意：备注里正常写手机号的可能性不小，`contact`、`link` 两个分类的系数要调低或关掉。

### 6. 积分要说明用途

积分只能抵扣自家的 AI 识别用量（`src/points/wallet.ts` 的 `reserveCall('speech'|'image'|'text')`），
不可兑换、不涉现金 —— 本身合规。但审核员光看「积分 + 每日进入发放」容易误解成营销奖励，
建议在积分页写一句「积分用于智能识别的用量抵扣」。详见 [points.md](points.md)。

### 7. 服务类目

确认后台类目是「工具」类（记账 / 效率）。若选了金融、理财相关类目，个人主体会有资质问题。

### 8. 登录页没有协议勾选

微信一键登录通常不强制勾选协议，但配合隐私政策入口会更稳。

## 三、已经做对的

- **不强制登录**：`app.js` 里明确写了「未登录也进首页。审核要求先浏览功能」，
  `pages/me` 有游客卡，各 tab 都能逛
- **没有超范围收集**：无位置、通讯录、手机号、微信头像昵称；改昵称是用户自己输入
- **除 tools 外没有 web-view**，也没有其它外链
- **导出账单**是用户导出自己的数据，不涉及共享
