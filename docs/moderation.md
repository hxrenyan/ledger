# 本地违禁词检查

`src/moderation/` 是一个纯本地的文本审核工具：输入一段文本，返回是否违规、违规可能性、0–100 分、命中明细和打码文本。不调用外部服务，不读写数据库，没有新增依赖。

**当前状态：只是工具类，还没有接入任何接口。** 接入哪些用户输入（反馈、交易备注、导入文本等），以及拦截后是拒绝还是打码保存，留到接入时再定。

## 文件

| 文件 | 内容 |
|------|------|
| `src/moderation/forbidden.ts` | 主类 `ForbiddenWordChecker`：匹配、打分、缓存、统计 |
| `src/moderation/normalize.ts` | 文本归一化：繁简、全角、同形字母、分隔符、叠字 |
| `src/moderation/ahoCorasick.ts` | 多模式匹配索引（Aho-Corasick） |
| `src/moderation/lexicon.ts` | 规则类型、内置示例词库、词库和白名单文件解析 |

## 快速上手

```ts
import { ForbiddenWordChecker } from './moderation/forbidden.ts'
import { readLexiconFile, readWhitelistFile } from './moderation/lexicon.ts'

// 内置示例词库 + 业务词库；同名规则以后者为准
const checker = ForbiddenWordChecker.withDefaults({
  words: readLexiconFile('data/forbidden.txt'),
  whitelist: readWhitelistFile('data/whitelist.txt'),
  options: { blockThreshold: 70, categoryWeights: { contact: 0.5, link: 0 } },
  lexiconVersion: 'v2026.10',
})

const r = checker.check('有事加 微信：abc_12345')
if (r.violated) {
  // r.score、r.reasons、r.masked …
}
```

不想要内置词库就用 `new ForbiddenWordChecker({ words, whitelist, patterns, combos, options })`。

内置词库只有十几个演示词和几条联系方式正则，正式使用必须换成自己的词库。

## 返回结果

| 字段 | 说明 |
|------|------|
| `violated` | 是否违规，等于 `level === 'block'` |
| `level` | `pass` 放行 / `review` 待审 / `block` 拦截 |
| `score` | 0–100 分 |
| `probability` | 违规可能性 0–1，等于 `score / 100` |
| `redline` | 是否命中红线规则 |
| `categories` | 每个分类各自的分数（已套用分类上限） |
| `hits` | 命中明细，见下表 |
| `reasons` | 可读的命中原因，与 `hits` 一一对应 |
| `masked` | 违禁词和正则命中处打码后的原文；组合规则不打码 |
| `truncated` | 文本超过 `maxLength`，超出部分没有检查 |
| `version` | `词库标签#修订号`，词库或配置每变一次修订号加一 |

每条命中 `hits[i]`：

| 字段 | 说明 |
|------|------|
| `kind` | `word` 违禁词 / `pattern` 正则 / `combo` 组合 |
| `rule` | 违禁词为主词，正则和组合为规则 id |
| `category` | 分类 |
| `text`、`start`、`end` | 原文命中片段，`[start, end)` 为 UTF-16 下标 |
| `weight` | 规则配置的权重 |
| `effectiveWeight` | 实际参与计分的权重 |
| `obfuscated`、`variants` | 是否规避写法，以及具体是哪几种（见下文） |
| `whitelisted` | 是否被白名单降权 |
| `redline` | 这条命中是否触发红线 |

`check` 返回的是独立副本，调用方可以随意修改，不会影响缓存。

## 规则类型

| 类型 | 作用 | 例子 |
|------|------|------|
| 违禁词 | 词条 + 权重 + 分类，可带别名 | `代开发票`，别名 `dkfp` |
| 正则 | 结构化特征 | 手机号、微信号、QQ、链接 |
| 组合 | 几个普通词在一个短窗口内同时出现才算命中 | `兼职` + `日结` + `垫付` 在 20 字内 |
| 红线 | 违禁词、正则、组合都可以标红线，命中直接 100 分拦截 | `冰毒` |
| 白名单 | 短语完整覆盖违禁词时降权或放行，可限定分类 | `反赌博` 只对赌博类降到 0.2 倍 |

违禁词的两个标记：

- `redline`：红线，命中即拦截，不看阈值。
- `exact`：只匹配原样写法，不做插字、叠字、夹杂、同音识别，适合容易误伤的短词。

正则规则注意：

- 正则跑在归一化后的文本上，已转小写、全角转半角，规则里按小写写。
- `dense: true` 时先去掉全部分隔符再匹配，用于 `b-e-t 3 6 5` 这类被拆开写的特征；命中位置仍对应原文。
- 添加时会拒绝嵌套量词（如 `(a+)+`、`(\w*)*`）和超过 500 字符的正则；单条规则单次最多计 100 个命中。

## 能识别的规避写法

| 写法 | 例子 | 结果里的标记 |
|------|------|--------------|
| 繁体 | `來玩網絡博彩` → 网络博彩 | 不算规避 |
| 全角、圈号等兼容字符 | `ｄｋｆｐ`、`ＱＱ` | 不算规避 |
| 西里尔/希腊同形字母 | `ѕb`（西里尔 ѕ）→ sb | 不算规避 |
| 插入空格、标点、符号、emoji | `赌 * 博`、`赌👨‍👩‍👧博` | `gap` 插字 |
| 零宽字符、组合符 | `赌\u200b博`、`赌̶博` | `hidden` 隐藏字符 |
| 叠字 | `赌赌赌博` | `repeat` 叠字 |
| 汉字之间夹字母数字 | `赌1博`、`网x络x博x彩` | `noise` 夹杂字母数字 |
| 同音字（需配置拼音） | `威信` → 微信、`兵毒` → 冰毒 | `homophone` 同音字 |
| 拼音连写（需配置拼音） | `du bo` → 赌博 | `pinyin` 拼音 |
| 别名 | 谐音、缩写、拆字，在词条里手工配置 | 不算规避 |

防误伤的处理：

- 插字间隔按可见字形计数，一个 emoji 组合序列算 1 个；超过 `maxGap`（默认 3）就不再视为同一个词，所以 `赌.....博` 不命中。
- 夹杂字母数字只对纯中文词条生效，且两侧必须是汉字、夹杂长度不超过 `maxNoise`（默认 2），所以 `第1博物馆`、`赌abc博` 不命中。
- 纯字母数字的词条要求两侧不紧贴字母数字，所以 `sb` 不会命中 `USB`，拼音别名 `dubo` 不会命中 `dubois`。
- 同音、拼音属于模糊匹配，只按权重计分，不触发红线。
- 有重叠命中时按「红线 → 高权重 → 长词」挑选，同一位置只计一次，避免低权重长词盖住红线词。

## 打分

每条命中的有效权重：

\[
w = \text{规则权重} \times \text{分类系数} \times \text{重复衰减}^{k-1} \times \text{白名单系数} \times \text{规避系数} \times \text{同音系数} \times \text{长文本系数}
\]

- 重复衰减：同一条规则第 \(k\) 次命中时乘以 `repeatDecay^(k-1)`，防止刷屏把分数堆满。
- 规避系数只在有规避写法时乘，同音系数只在同音或拼音命中时乘。
- 长文本系数只对非红线命中生效，默认关闭。

合成方式是概率并集：

\[
\text{分类分} = \min\left(\text{分类上限},\ 100 \times \left(1 - \prod (1 - w_i/100)\right)\right)
\]

总分再把各分类分按同样方式合成。命中红线时总分直接为 100。

效果：单个高权重词的分数接近它自己的权重；多个低权重命中会逐步累积，但不会超过 100。

最后按阈值判定：`score ≥ blockThreshold` 拦截，`score ≥ reviewThreshold` 待审，否则放行。

## 配置项

打分配置 `options`，可以在构造时传、用 `setOptions` 改全局，或者在单次 `check(text, override)` 里临时覆盖：

| 配置 | 默认 | 说明 |
|------|------|------|
| `blockThreshold` | 60 | 达到即拦截 |
| `reviewThreshold` | 30 | 达到即待审；大于拦截阈值时按拦截阈值处理 |
| `categoryWeights` | 每类 1 | 分类系数；设为 0 关闭该分类，红线也一起关 |
| `categoryCaps` | 每类 100 | 分类分数上限，例如联系方式类最多 30 分 |
| `repeatDecay` | 0.5 | 重复命中衰减 |
| `obfuscatedFactor` | 0.9 | 规避写法系数 |
| `homophoneFactor` | 0.7 | 同音、拼音命中系数 |
| `maxGap` | 3 | 词内两个字之间最多跳过几个可见分隔字形 |
| `maxNoise` | 2 | 汉字之间最多夹几个字母数字，0 关闭 |
| `lengthReference` | 0（关闭） | 长文本折算基准字数；超出后非红线命中乘以 \(\sqrt{\text{基准}/\text{长度}}\) |
| `maskChar` | `*` | 打码字符 |
| `maxLength` | 50000 | 超出部分不检查 |

构造配置：

| 配置 | 默认 | 说明 |
|------|------|------|
| `words` / `whitelist` / `patterns` / `combos` | 空 | 规则，`withDefaults` 会叠加内置示例 |
| `normalize.charMap` | 无 | 追加字符映射，如 `{ '薇': '微', '0': 'o' }` |
| `normalize.collapseRepeat` | true | 是否合并叠字 |
| `homophone` | 无 | 同音识别，见下文 |
| `cacheSize` | 1000 | 结果缓存条数，0 关闭；只缓存 2000 字以内的文本 |
| `lexiconVersion` | `local` | 词库版本标签，写进结果的 `version` |

归一化和同音配置会影响索引，只能在构造时设置。

## 词库文件格式

违禁词，每行一条，`#` 开头为注释：

```text
# 词条[/别名1/别名2]|权重|分类|标记
代开发票/代开fp/dkfp|80|fraud
冰毒|95|drugs|redline
操|30|abuse|exact
```

权重 0–100 必填；分类可省略，默认 `default`；标记可选 `redline`、`exact`，多个用逗号分隔。格式错误会抛出带行号的异常。

白名单，每行一条：

```text
# 短语[|系数|分类1,分类2]
反赌博|0.2|gambling
禁赌||gambling
操作
```

系数 0–1，省略为 0（完全放行）；分类省略表示对所有分类生效。

对应函数：`parseLexicon` / `readLexiconFile`、`parseWhitelist` / `readWhitelistFile`。

## 同音字和拼音

需要传入一个「单个汉字 → 不带声调拼音」的函数，工具本身不带拼音字典，可以接 `pinyin-pro` 这类库：

```ts
const checker = ForbiddenWordChecker.withDefaults({
  homophone: { pinyin: (ch) => toPinyin(ch) },
})
```

- 只有至少两个汉字、全部能转拼音、没有标 `exact` 的词条参与同音匹配；单字同音误伤太高，不做。
- `pinyinAlias`（默认 true）会把多音节词的拼音连写自动当作别名，用来识别 `weixin`、`du bo`。
- 每个字只取一个读音，多音字可能识别不全。

## 运行时管理

| 方法 | 说明 |
|------|------|
| `addWords` / `removeWords` | 增删违禁词；按主词或别名删除，会连同全部别名一起删 |
| `addWhitelist` / `removeWhitelist` | 增删白名单 |
| `addPatterns` / `addCombos` / `removeRules` | 增删正则和组合规则 |
| `setOptions` | 修改全局打分配置 |
| `check` / `checkMany` | 检查单条 / 多条 |
| `stats()` | 词条数、索引键数、白名单数、规则数、当前版本 |
| `metrics(top)` | 检查总数、缓存命中数、各级别数量、命中最多的规则 |
| `resetMetrics()` | 统计清零 |

任何增删或改配置都会让修订号加一并清空缓存。增删词后，下一次检查会重建整个索引（10 万词约 0.15 秒），所以大词库要批量修改，不要逐个改。

## 性能

本机 Node 22 单线程实测，测检查速度时关闭缓存：

| 文本长度 | 单次耗时 | 每秒次数 |
|----------|----------|----------|
| 30 字 | 约 10µs | 9–10 万次 |
| 500 字 | 0.11–0.14ms | 7000–9000 次 |
| 1 万字 | 2.1–2.6ms | 约 400 次 |
| 30 字，命中缓存 | 约 2µs | 约 50 万次 |

| 词库规模 | 常驻内存 | 录入词库 | 首次构建索引 |
|----------|----------|----------|--------------|
| 1 千词 | 约 0.4MB | 6ms | 4ms |
| 1 万词 | 约 2.2MB | 20ms | 22ms |
| 10 万词 | 约 19MB | 140ms | 150ms |

- 检查速度基本不受词库大小影响，10 万词比 1 千词慢约 20%。
- 检查 5 万字文本的临时内存 0.4–4.6MB，检查完即回收；缓存存满 1000 条短文本约多占 0.4MB。
- 线上是 Sealos 单副本容器，上 10 万词量级的词库前要先确认内存配额。

性能上做过的处理：

- 普通文本逐字走快速路径，只有含组合符、emoji 组合序列等字符时才按字形切分；常用汉字和 ASCII 直接查表，其他字符的归一化结果会被记住。
- 归一化后的文本按列存成定长数组，检查时几乎不逐字创建对象。
- 匹配索引构建完压缩成数组：子节点排序后二分查找，根节点直接查表，输出不在每个节点重复复制。
- 组合规则复用同一套匹配索引，最短窗口用滑动窗口加单调队列。

## 注意事项

- 内置白名单对 `反赌博`、`打击赌博` 是降到 0.2 倍，不是完全放行，所以「社区开展反赌博宣传」得 14 分（仍是放行）；要完全放行把系数设为 0。
- 内置正则会给手机号、链接打分。记账备注里正常写手机号的可能性不小，接入时按场景把 `contact`、`link` 分类的系数调低或设为 0。
- 跳过分隔符拼词存在跨标点误伤的可能，可以调小 `maxGap`、调低 `obfuscatedFactor`，或者加白名单。
- 繁简对照只收录约 200 个违禁词高频字，其余用 `normalize.charMap` 追加。
- 正则安全检查只拦常见的危险写法；规则来自外部配置时仍建议人工审核，或改用 `re2` 这类不回溯的正则引擎。
- 没有自动化测试。改词库或算法时，至少回归这几类样本：正常文本不误伤、各种规避写法能识别、白名单与红线行为符合预期。
