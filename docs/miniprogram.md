# 小程序关于与版本

管理后台「产品配置 → 小程序」改两件事：关于弹窗的文字，以及正式版最低可用版本。存在 `app_configs` 的 `miniprogram.client`，改完即生效，不用发小程序。

## 关于记账

「我的 → 关于记账」仍是一个弹窗。标题 1–20 字，正文 1–400 字。没配过时标题是「记账」，正文仍是原来那段说明。

点「关于记账」时重新读取。启动和回到前台也会读一次，用来判断要不要强制更新。读失败时弹窗仍用上一次的结果，没有上一次就用默认文案。

已经发布到微信上的那一版，关于文字写在安装包里，不读这个接口。要等带这次改动的小程序发出去之后，后台再改才会出现在弹窗里。

## 必须更新

最低版本留空，不限制。填写 `1.2.0` 这种版本号后，正式版低于它就不能继续用：

- 比较按点分段，缺的段当 0。`1.2` 和 `1.2.0` 相同。当前版本空着或格式不对，视为低于任何已填写的最低版本。
- 只拦正式版。开发版和体验版的版本号经常是空的，不拦截，避免调试进不去。
- 被拦住时进入 `pages/force-update/`，不能回到明细、人情、工具、我的。
- 启动和首次回前台共用进行中的版本检查；检查结束后才尝试领取进入积分。门槛生效后，即使旧请求返回登录过期、登录回调迟到或点击「先看看」，也会停留在更新页。
- 微信下好新版本后直接重新进入，不再询问。下不到新版本时，更新页立即显示失败状态和删除小程序后重新搜索打开的指引，无需再次进入页面。「重新检查」只重新读取版本门槛；更新包尚未就绪时保留失败提示，不会声称已重新开始下载。后台解除门槛后可返回首页。
- 更新提示最多 80 字。留空则用「当前版本已停用，请更新后继续使用。」

接口不用登录：

- `GET /api/v1/app/client?version=1.1.0` → `{ about_title, about_body, min_version, update_required, update_message }`
- `GET /api/v1/admin/miniprogram` 读取当前配置
- `PUT /api/v1/admin/miniprogram`，body `{ about_title, about_body, min_version, update_message }`

最低版本不是 `1`、`1.2` 或 `1.2.3` 这种格式时，保存会被拒绝。

## 账本页上的用户

管理后台「账本」每一行列出这个账本里的人：昵称、账号、是否主人、是否停用。搜索账本名、主人或任一成员的账号和昵称，都能找到这本账本。

`GET /api/v1/admin/ledgers` 的每条增加 `members: [{ id, username, nickname, role, disabled }]`。主人排在前面。
