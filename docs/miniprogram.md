# 小程序设置、快捷记账与版本

管理后台「产品配置 → 小程序」改两件事：关于弹窗的文字，以及正式版最低可用版本。存在 `app_configs` 的 `miniprogram.client`，改完即生效，不用发小程序。

## 我的与登录

「我的」提供个人资料、积分、账本切换、资产与预算概览，以及分类管理、周期记账、账单导入等入口。这里不再展示「绑定已有账号」和「智能记账」；「我的 → 设置」统一管理记录人展示和明细「＋」菜单。智能记账保留在「＋」菜单中，不再提供独立悬浮按钮。

「账单导入」位于「导出账单备份」正上方，两项共用列表行样式；点击导入进入原有账单文件或文本导入页。

登录页与明细页共用蓝色主色、浅灰背景和白色卡片。支持微信一键登录、用户名密码登录和注册，以及先以游客浏览。已有用户名密码账号的用户，可用原账号登录；首次微信登录会创建独立账号，小程序不提供账号合并入口。

本次页面调整不改登录接口及请求、返回字段，也不影响余额、收据和统计。

## 快捷记账与可拖动入口

明细页无数据时，「＋ 记一笔 / 智能记账」两个按钮文字水平、垂直居中，仍是固定的空态快捷入口，不受「＋」菜单配置影响。独立悬浮的「智能记账」按钮已移除，页面只保留可拖动的圆形「＋」。权限、模型可用性和积分规则不变；未登录时先进入登录页。

「我的 → 设置 → 明细『＋』入口」列出五项：记一笔、记人情、智能记账、日历记录、账单导入。每项压缩为紧凑的单行：小图标、名称、开关和右侧拖动手柄。每项可开启或隐藏，按住右侧三横线手柄上下拖动调整顺序（包括隐藏项，重新开启仍在原位置），不再提供「上移 / 下移」按钮。拖动时当前行高亮并跟随手指，其他项即时让位，松手保存；系统取消触摸或离开页面则撤销这次未保存的排序。开关区域不触发拖动，手柄拖动不会滚动页面。默认全部开启，顺序如上。至少保留一个入口，关闭最后一项会提示并恢复开关。修改立即保存，无需另点保存。

点击明细「＋」时读取最新配置，并过滤当前不可用的识别能力。可用入口多于一项时按配置顺序显示菜单；只剩一项则直接执行对应功能：记一笔 / 记人情 / 导入进入原表单，智能记账打开识别面板，日历记录打开日历识别面板。若启用的入口当前全不可用，提示到设置调整，不擅自改成其他功能。人情页「＋」仍直接记人情，不受明细菜单配置影响。

明细和人情页「＋」均可拖动，拖动后不会误触。入口限制在当前窗口可用区域内，避开底部安全区；松手后按窗口比例记录位置，再次进入、切换明细/人情或窗口尺寸变化时恢复，两页共用本机位置。位置只保存在当前设备，清理小程序数据后回到默认右下角。

设置页也允许游客进入；记录人开关和菜单配置按账号保存在当前设备，不随退出登录清除，不同步到其他设备，游客使用独立配置。新增菜单配置不覆盖原记录人开关缓存。以上均为前端偏好，不新增后端接口或请求参数。

## 展示记录人

「我的 → 设置 → 显示偏好」提供「展示记录人」开关，不再直接放在「我的」列表中。默认开启，按登录账号保存在当前设备；退出后重新登录同一账号仍保留，不同步到其他设备。单人账本始终隐藏，多人账本仅在开关开启时显示。

显示范围是明细流水列表、明细日历的当天流水、人情列表和联系人往来明细。记录人取记录的原始 `created_by` 对应用户，优先显示当前昵称（去掉首尾空格），昵称为空则显示账号；用户不存在时显示「未知记录人」。编辑记录不会把记录人改成编辑者。成员离开后仍保留原记录归属，但当前成员数变为一人时不再展示。

接口契约（无需增加请求参数，原有账本鉴权和筛选不变）：

- `GET /api/v1/transactions`：保留 `month`、`items`，增加顶层 `member_count`（当前账本成员数）；每个 `items[]` 增加 `created_by_name`（记录人显示名）。
- `GET /api/v1/gifts`：保留 `items`，增加同样的 `member_count` 和 `items[].created_by_name`；传 `contact_id` 时也返回上述字段。
- 记录详情和新增、编辑接口返回结构不变；前端展示规则为 `member_count > 1 && 展示记录人开关开启`。返回旧版接口、尚未取得成员数时保守隐藏。

以上只改变展示和快捷入口，不改变记录写入、余额、收据、收支统计和人情统计，也不涉及数据库结构变更。

## 关于记账

「我的 → 关于记账」仍是一个弹窗。标题 1–20 字，正文 1–400 字。没配过时标题是「记账」，正文仍是原来那段说明。

点「关于记账」时重新读取。启动和回到前台也会读一次，用来判断要不要强制更新。读失败时弹窗仍用上一次的结果，没有上一次就用默认文案。

已经发布到微信上的那一版，关于文字写在安装包里，不读这个接口。要等带这次改动的小程序发出去之后，后台再改才会出现在弹窗里。

## 必须更新

最低版本留空，不限制。填写 `1.2.0` 这种版本号后，正式版低于它就不能继续用：

- 比较按点分段，缺的段当 0。`1.2` 和 `1.2.0` 相同。当前版本空着或格式不对，视为低于任何已填写的最低版本。
- 只拦正式版。开发版和体验版的版本号经常是空的，不拦截，避免调试进不去。
- 被拦住时进入 `pages/force-update/`，不能回到明细、人情、工具、我的。
- 启动和首次回前台共用进行中的版本检查；检查结束后才尝试领取进入积分。门槛生效后，即使旧请求返回登录过期、登录回调迟到或点击「先看看」，也会停留在更新页。
- 微信下好新版本后直接重新进入，不再询问。下不到新版本时，更新页立即显示失败状态和删除小程序后重新搜索打开的指引，无需再次进入页面。「重新检查」只重新读取版本门槛；更新包尚未就绪时保留失败提示，不会声称已重新开始下载。后台解除门槛后可返回首页。
- 更新提示最多 80 字。留空则用「当前版本已停用，请更新后继续使用。」

接口不用登录：

- `GET /api/v1/app/client?version=1.1.0` → `{ about_title, about_body, min_version, update_required, update_message }`
- `GET /api/v1/admin/miniprogram` 读取当前配置
- `PUT /api/v1/admin/miniprogram`，body `{ about_title, about_body, min_version, update_message }`

最低版本不是 `1`、`1.2` 或 `1.2.3` 这种格式时，保存会被拒绝。

## 账本页上的用户

管理后台「账本」每一行列出这个账本里的人：昵称、账号、是否主人、是否停用。搜索账本名、主人或任一成员的账号和昵称，都能找到这本账本。

`GET /api/v1/admin/ledgers` 的每条增加 `members: [{ id, username, nickname, role, disabled }]`。主人排在前面。
