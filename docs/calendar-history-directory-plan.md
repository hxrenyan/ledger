# 日历记录：年月目录详细方案

状态：已实现，本地验收通过，微信真机待验。方案日期：2026-10-24；实施日期：2026-10-26。当前行为以 `docs/tools.md` 为准。

## 1. 目标与范围

- 目标：不要求记住年月或关键词，通过「年份 → 有记录的月份 → 正文预览」找回历史记事。
- 首期交付：日历顶部常驻入口、历史年月目录、所选月份正文预览、跨月连续浏览、定位原记录；原生小程序与 H5 同步支持。
- 成功标准：从日历打开目录、选择年份、选择月份，三次点击内能看到任意一个有历史记录月份的正文；空年月自动跳过，目录支持完整历史。
- 本期不做：向量、AI 问答、全历史关键词搜索、标签分类、独立的全量时间轴、另一套编辑删除界面。
- 数据口径：按记事所属日期 `day` 归档，截止日为服务端上海当天，包含今天；补记旧事进入其所属年月，未来安排继续在原日历查看。
- 业务边界：记事归登录用户，不归账本；不影响流水、余额、收据、统计和积分，不引入外部服务或调整线上配置。

## 2. 已核实的现状与方案取舍

- 页面已有月历、当天记事、记事一览三块，以及年月选择器；直接跳月仍依赖用户记得年月。
- 原生页面为 `miniprogram/pages/tool-calendar/tool-calendar.{js,wxml,wxss}`，H5 为 `web/src/pages/tools/CalendarPage.vue`，共用后端。
- `src/routes/dayNotes.ts` 已提供月、日、最长一年范围的查询；月查询返回该月正文。关键词搜索目前在页面内过滤选中月前后各五个月的结果。
- 日期切换、保存和搜索已有请求代次及编辑会话保护。`applyMonth` 等路径会取消编辑，目录预览不能直接调用这些方法。
- `day_notes` 已有 `(user_id, day, created_at)` 索引；首期复用原表和索引，不创建归档副本或预聚合表。

## 3. 页面与交互

### 3.1 入口与布局

- 月历卡顶部操作区增加文字按钮「历史」，与「回今天」「收起」同级；日历收起时入口仍可见。
- 窄屏时顶栏保持同一行，收紧间距、按钮横向留白与月份切换宽度；保留完整年月、历史、回今天与展开／收起操作，以及按钮高度。
- 点击打开大尺寸底部弹层，标题和关闭按钮固定，内容区独立滚动。H5 桌面端限制弹层宽度；小程序处理底部安全区。
- 展示「截至 YYYY-MM-DD · 共 N 条 · M 个记录日」。下图为交互示意，数字与正文均为虚构示例。

  [3 月 · 3 条 / 2 天]

### 3.2 年份、月份与默认选择

- 年份从近到远排列，只列有历史记事的年份，不使用固定「最近十年」下限；每年显示条数、活跃月份数。
- 一次展开一个年份；年内月份从近到远排列，只列有记录的月份，每月显示条数和记录天数。
- 同一页面再次打开优先恢复上次浏览年月；首次打开优先当前日历选中月，其次选中年份最近有记录月，最后回退到整个历史最近有记录月。
- 恢复的年月已被删空时，按以上回退规则选取，并提示「原月份已无历史记录，已显示最近记录」。
- 点年份只切换目录展开项，默认预览该年最近有记录月；点月份加载其正文，不关闭弹层、不改变主日历。
- 「更早／更新有记录的月份」沿全部活跃月份顺序导航，跨年自动切换展开年份；到边界禁用对应按钮。

### 3.3 正文预览与查看当天

- 正文按天分组，日期从近到远；同一天内按 `created_at ASC, id ASC` 展示，保持既有写入顺序。
- 每条显示完整正文，允许正常换行；无需先点标题才能判断内容。日期标题显示记录条数。
- 大月份初始渲染三十条，点「继续查看本月」追加三十条；说明当前已显示／总条数，不制造已经到底的错觉。
- 首期月查询仍一次返回该月内容，上述分批只限制渲染量，不等同于服务端分页；是否扩展分页以大月份实测结果决定。
- 只有点「查看当天」才提交导航：清除主页面旧搜索，切回「本月」筛选并展开当天记事，避免「今起」隐藏历史记录。
- 导航复用日期选择和加载链路，携带目标 `day`、`id`；加载完成且节点渲染后滚动到该条，并短暂高亮，不自动进入编辑。
- 目标日加载失败时保留目录选择与可重试入口；若重新读取后确认条目已不存在，明确提示并刷新目录及预览，不定位到其他条目冒充成功。
- 查看当天后再次点「历史」，恢复原年月与正文滚动位置，刷新成功后按条目锚点恢复；锚点不存在时回到该月标题。

### 3.4 草稿、返回与关闭

- 打开、关闭、展开年份和预览月份均不改动主日历的日期、正文草稿、编辑会话、筛选与滚动位置。
- 有未保存正文时点「查看当天」，先确认「继续编辑／放弃修改并查看」；取消后保留目录状态及原草稿。
- 正在保存时仍可看目录，暂缓提交「查看当天」并提示等待保存结束，避免新增导航与保存回调交叉清空草稿。
- 关闭按钮、遮罩和 H5 的 Esc 关闭目录；小程序系统返回沿用页面原有行为。弹层滚动与手势不触发底层日历切月。
- H5 打开后焦点进入弹层、Tab 保持在弹层内，关闭后回到入口；小程序真机验收系统返回及手势行为。

## 4. 接口与数据口径

### 4.1 目录汇总接口

`GET /api/v1/day-notes/history`；沿用登录和当前账本访问校验，只读取 `user_id = 当前用户`，不接受客户端指定用户。

```json
{
  "as_of": "2026-10-24",
  "total_count": 3,
  "recorded_days": 2,
  "years": [
    {
      "year": 2024, "count": 3, "recorded_days": 2,
      "months": [
        {"month": "2024-03", "count": 3, "recorded_days": 2, "first_day": "2024-03-05", "last_day": "2024-03-18"}
      ]
    }
  ]
}
```

- 上述为响应示例；数值字段为数字，年月格式统一，年和月均倒序。活跃年、月数量由数组长度得到。
- `as_of` 由既有 `shanghaiDate()` 生成；统计条件为 `day <= as_of`，当前月未来日期也不计入。
- `count` 是条数，`recorded_days` 是去重后的天数；一天多条时条数增加，天数不重复计算。
- 无历史记录返回 `total_count: 0`、`recorded_days: 0`、`years: []`；未登录或无账本权限沿用既有错误契约。
- 响应设置 `Cache-Control: no-store`；不带记事正文，不受主页面搜索词或「今起」筛选影响。

### 4.2 正文查询与刷新

- 复用 `GET /api/v1/day-notes?month=YYYY-MM` 获取预览正文；目录预览显式过滤 `day <= as_of`，主日历仍展示该月完整安排。
- 月份和条目归属以服务端数据为准；首期不提供目录内编辑删除，进入原界面操作后再次打开目录即刷新。
- 每次打开重新取汇总，再取选中月正文；浏览年月和滚动锚点只存在当前页面会话，正文不持久缓存。
- 新增、删除成功或账号合并后使目录状态失效；正文修改使预览失效。账号切换时清空全部目录状态。
- 汇总与月查询不是数据库快照：过滤后的条数、天数若与汇总不同，自动重取汇总一次；仍变化时提示「记录有更新，点击刷新」，不无限重试。
- 跨上海零点重新打开时重取截止日；已经打开的目录明确显示原截止日，刷新后才纳入新一天。

### 4.3 聚合与性能边界

```sql
SELECT substr(day, 1, 7) AS month, COUNT(*) AS count,
       COUNT(DISTINCT day) AS recorded_days,
       MIN(day) AS first_day, MAX(day) AS last_day
FROM day_notes
WHERE user_id = ? AND day <= ?
GROUP BY substr(day, 1, 7)
ORDER BY month DESC;
```

- 参数为登录用户和上海截止日；在应用层归并成年份并计算总数，单次汇总查询，不按月份循环查库。
- 聚合只读日期和计数所需数据；复用现有索引前缀，实施时用 `EXPLAIN QUERY PLAN` 验证，不提前增加索引。
- 查询草案已在按权威 schema 建立的内存样例库验证：使用现有覆盖索引，分组和去重使用临时 B 树；仅验证可执行性与边界，不代表部署环境的性能结论。
- 历史聚合仍需要处理该用户历史记录，不承诺只按月份数量计算；测量实际数据量、耗时与响应体后再评估优化。
- 首期无表结构变更、无外键、无数据搬迁；若实施中确需索引或结构调整，另行同步权威 schema 与迁移并验证。

## 5. 状态隔离与异常处理

- 独立状态：是否打开、截止日、年份汇总、展开年份、选中月份、预览分组、已显示条数、加载错误、滚动锚点。
- 汇总、预览各自有请求代次；切月、关闭、账号变化后旧响应不可更新当前目录，目录请求也不可覆盖主日历状态。
- 加载时显示骨架，快速切月时先清除旧正文；失败显示「加载失败，重试」，不能把请求失败显示成「没有记录」。
- 无历史时统一提示「暂时没有历史记录」，提供「回日历」入口，并说明「未来安排仍在日历中查看」；不把无历史等同于没有任何记事。
- 某月删空后移除该月；某年删空后移除该年；删除最后一条后进入明确的空态，记事主体仍由既有接口管理。

## 8. 风险与撤销

| 风险 | 处理方式 |
| --- | --- |
| 只有数字仍难回忆 | 目录内直接展示月份正文，提供有记录月份的连续浏览 |
| 大月份响应／渲染变慢 | 首屏分批渲染，实测响应；必要时单独扩展服务端分页 |
| 主页面草稿丢失、旧请求串页 | 目录状态独立，请求代次校验；真正跳转前处理草稿并等待保存结束 |
| 未来数据与今天边界不一致 | 服务端给截止日，统计和预览用同一截止日，目录明示范围 |
| 数据变化造成数量过期 | 重开刷新、写后失效、差异时一次重取，持续变化由用户主动刷新 |
| 原生与 H5 发布不同步 | 后端新增接口保持兼容；先后端、再 H5、再小程序正式版，逐端验收 |

- 撤销触发：出现用户串数据、草稿丢失、定位错误或明显性能退化时，立即停用新入口并按原部署流程回退。
- H5／后端回退到前一应用版本；原生回退遵循小程序版本发布与平台能力。新增接口保持兼容，旧端仍可使用原日历。
- 没有数据库迁移，不需要恢复记事数据；首期不另增远程开关或改动线上配置。回退耗时取决于既有发布及平台流程，当前不承诺分钟数。
