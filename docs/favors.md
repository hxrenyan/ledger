# 人情往来

人情本身不进账户余额，也不进收支统计。记新的人情时可以再记一笔支出或收入，那笔才计入账户。认得出对方是人名，就记到 `gifts`；商家、工资、平台名仍是普通明细。

小程序在导入预览、智能记账核对、改一笔、改一条人情时，都可以在「明细」和「人情」之间改。H5 目前没有这两处切换，也没有互转入口。

## 什么算人名

2 到 4 个汉字，且整段不像商家或款项名。下面这些词出现在名字里就不算人名：微信、支付宝、美团、饿了么、京东、淘宝、拼多多、银行、转账、商户、收款、付款、红包、余额、零钱、工资、奖金、报销、退款、利息、理财、餐厅、饭店、超市、商店、公司、酒店、商场、医院、药房、学校、集团、中心、平台、咖啡、奶茶。

口语和账单备注用同一套抽取（`src/imports/favor.ts`）：

| 写法 | 结果 |
|------|------|
| `给张三转了500`、`送给李四红包` | 人名张三 / 李四，送出 |
| `张三随礼`、`李四的礼金` | 人名，送出 |
| `收到王五200` | 人名王五，收到 |
| `美团红包`、`收到工资8000` | 普通明细，没有人名 |

事由只认这些：结婚、满月、搬家、寿宴、升学、丧事、过年、生日。对不上就留空。方向优先看句子里的「收到 / 给」，否则支出当送出、收入当收到。

## 导入、说话、拍照

预览不落库。提交时带了 `favor_contact` 才写进 `gifts`，否则写普通流水。

| 来源 | 默认 |
|------|------|
| 表格 | 备注、对方、分类拼在一起能抽出人名，就当人情。抽不出时，对方栏本身是人名（且这一行是支出或收入）也当人情，事由留空。商家名留在明细 |
| 口语 / 拍照 | 模型给出的人名优先；没有合法姓名再走上面的规则。没给送出/收到时，按这一行的收支方向补 |

模型提示里约定：转账、红包、随礼、收款对象是人名时写入 `favor_contact`；商家可以留在对方栏，不要改成人名；微信、支付宝、美团、银行、工资、报销不要写进人名。

小程序导入预览和智能记账核对，每一行有「明细 / 人情」切换。切到人情会带上已有的对方姓名，提交时姓名为空会拦住，提示「人情要填对方姓名」。切回明细则这一行不带 `favor_contact`。从人情入口进来的智能记账，行默认是人情，仍要填姓名。

智能记账里，行是人情时下面有「同时记明细」，默认关。关着只写往来，不要求账户，也不动余额。打开后按这一行已选的账户和分类再写一笔流水，方向跟收支一致。提交字段是 `also_tx: false`；不传这个字段时，人情和流水都写（账单导入仍是这样）。

批次撤销会一并删掉这批产生的人情。见 [import.md](import.md)。

## 记的时候可以同时记明细

只在新建人情时。`POST /api/v1/gifts` 同时带上 `account_id` 和 `category_id`，同一次写入再记一笔流水：

| 人情 | 明细 |
|------|------|
| `give` 送出 | `expense` 支出，分类必须是支出 |
| `receive` 收到 | `income` 收入，分类必须是收入 |

金额、日期和人情相同。备注空着时，明细备注用联系人姓名。账户余额只被这笔记账改动。两条记录之后各自存在：删人情不会删明细，改人情也不会改那笔明细。

只传账户或只传分类会 400。改人情（`PATCH`）不看这两个字段。从明细转成人情也不会再记一笔，否则同一笔钱会计两次。

小程序记人情页有「同时记明细」。打开后选分类和账户。改人情、转成人情不显示这个开关。智能记账的人情行用同一个开关，见上一节。

## 已经记下的，可以互转

两条接口都要用户 JWT 和 `X-Ledger-Id`。同一次 `db.batch` 里改余额、删旧记录、写新记录。

| 方法 | 路径 | 行为 |
|------|------|------|
| POST | `/api/v1/transactions/:id/to-gift` | 支出/收入改记成人情。冲掉这笔对账户的影响，删掉流水和收据，写成一条往来。返回 201 的人情 |
| POST | `/api/v1/gifts/:id/to-transaction` | 人情改记成明细。删掉往来，按所选账户和分类记一笔流水并计入余额。返回 201 的流水 |

明细转人情的 body：

| 字段 | 说明 |
|------|------|
| `contact_id` | 必填，须是本账本的联系人 |
| `kind` | `give` 或 `receive`。不传时，收入流水当收到，其余当送出 |
| `amount_cents` | 不传就用原流水金额 |
| `date` | `YYYY-MM-DD`。不传就用现在 |
| `occasion` | 最多 16 字 |
| `note` | 最多 200 字。不传就用原备注 |

转账会 400（`转账不能转成人情`）。流水不存在 404。

人情转明细的 body：

| 字段 | 说明 |
|------|------|
| `kind` | 必填，`expense` 或 `income` |
| `amount_cents` | 必填 |
| `account_id` | 必填，且未归档 |
| `category_id` | 必填，未归档，类型要和 `kind` 一致 |
| `date` | 可选。带 `time`（`HH:mm`）时记到那一分钟 |
| `note` | 最多 200 字 |
| `excluded` | 为真则不计入收支 |

小程序：改一笔（非转账）底部是「转成人情」，确认后进入记人情页，带上金额、日期、备注和方向；保存走上面的转人情接口，成功后回到明细。改一条人情底部是「转成明细」，确认后进入记一笔，保存走转明细接口。备注从上一页表单直接读取，不放进页面地址。已经变成百分号编码或拉丁乱码的，打开时还原成原文。人情不带收据，转成明细后也没有收据。

## 联系人

某人往来页右上角「编辑」可以改姓名（1–32 字，空的不提交）和关系（最多 16 字，可以清空）。接口是已有的 `PATCH /api/v1/contacts/:id`，body `{ name }` 或 `{ relation }`。
